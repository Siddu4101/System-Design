# 🧠 System Design Roadmap (Beginner → Interview-Ready)

## 🟢 PHASE 0: Mindset (Very Important)

Before starting, understand:

- System Design ≠ Coding
- There is no single correct answer
- Interviewers judge:
  - Clarity
  - Trade-offs
  - Scalability thinking
- 📌 Always think aloud in interviews

## 🟢 PHASE 1: Foundations (Week 1–2)

👉 **Goal:** Learn core building blocks

### Topics to Cover
- What is System Design?
- Scalability vs. Performance
- Latency vs. Throughput
- Vertical vs. Horizontal scaling
- CAP theorem
- ACID vs. BASE
- Stateless vs. Stateful services

### 🔥 Best YouTube Resources
#### English
- Gaurav Sen – System Design Basics
- ByteByteGo – System Design Concepts
- Hussein Nasser – Backend architecture

#### Hindi
- Tech Dummies Narendra L – System Design Playlist
- Engineering Digest (Hindi explanations mixed)

### 🎓 Udemy (Optional but Excellent)
- “Mastering the System Design Interview” – Frank Kane
- “System Design Interview Guide” – Exponent

📌 **Output of Phase 1:**  
You should be able to explain CAP theorem, scaling, and latency in simple words.

## 🟢 PHASE 2: Core Components (Week 3–4)

👉 **Goal:** Understand what real systems are made of

### Topics
- Load Balancers (L4 vs. L7)
- Databases
  - SQL vs. NoSQL
  - Indexing
  - Replication
- Caching
  - Redis
  - Cache eviction (LRU, LFU)
- Message Queues
  - Kafka
  - RabbitMQ
- CDN

### Best YouTube
- ByteByteGo (must watch)
- Gaurav Sen (DB sharding, caching)
- Hussein Nasser (deep understanding)

### Practice
After each topic:  
“Where would I use this in a real system?”

📌 **Output:**  
You should know when and why to use cache, queue, or DB type.

## 🟢 PHASE 3: Scalability Techniques (Week 5)

👉 **Goal:** Think like a backend architect

### Topics
- Database sharding
- Consistent hashing
- Rate limiting (Token bucket, Leaky bucket)
- ID generation (Snowflake)
- Read-heavy vs. Write-heavy systems
- Async vs. Sync communication

### Must-Watch
- Gaurav Sen – Consistent Hashing
- ByteByteGo – Rate Limiter
- SystemDesignPrimer (GitHub)

📌 **Output:**  
You can design for millions of users on paper.

## 🟢 PHASE 4: Classic System Design Problems (Week 6–8)

👉 **Goal:** Interview confidence

### MUST DO Problems
- URL Shortener
- Rate Limiter
- Notification System
- Chat Application
- File Storage (Google Drive)
- Feed System (Instagram / Twitter)

### How to Approach EVERY Problem
Use this structure ⬇️
1. Clarify requirements
2. Estimate scale
3. High-level architecture
4. DB design
5. Scalability
6. Bottlenecks & trade-offs

### Best Resources
- Gaurav Sen (problem solving)
- Exponent YouTube channel
- System Design Interview – Alex Xu (Book ⭐⭐⭐⭐⭐)

📌 **Output:**  
You can confidently whiteboard any system.

## 🟢 PHASE 5: LLD Touch (Week 9)

👉 Only enough to survive deep dives

### Topics
- API design
- Class diagrams (basic)
- Thread safety
- Design patterns (Factory, Strategy)

📌 **Remember:**  
Interviewers won’t expect full LLD from 2–3 YOE.

## 🟢 PHASE 6: Mock Interviews (Week 10–12)

👉 This is where most people fail — don’t skip

### Practice
- Record yourself explaining designs
- Use Excalidraw / Draw.io
- Explain to a friend or to me

### Platforms
- Pramp
- Interviewing.io
- Exponent mock interviews

## 🟢 DAILY ROUTINE (Simple & Effective)

- 📺 1 video (30–45 min)
- ✍️ Redraw architecture
- 🗣️ Explain aloud for 5 min

## 📌 FINAL ADVICE (Very Important)

- Don’t over-optimize early
- Don’t memorize designs
- Focus on reasoning
- You already have 2.4 YOE, so you are in a perfect position to crack System Design interviews 🚀
